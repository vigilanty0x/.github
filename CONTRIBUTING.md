# Contributing

Thank you for improving the public portfolio.

1. Open or reference an issue that states the observed behavior, expected
   behavior, scope, and evidence.
2. Keep the change focused and use synthetic fixtures only.
3. Add a positive test and a counter-proof that fails when the control is
   removed or the defect is reintroduced.
4. Run the repository's documented checks from a clean checkout.
5. Describe compatibility, migration, rollback, and residual risk in the pull
   request.
6. Disclose material AI assistance and verify every generated claim and change.

Do not include credentials, customer data, internal prompts, non-public service
coordinates, or production-derived examples.
